# UX — 思想

壁打ち確定版（2026-08-01）。renso ナレッジ: `umamusume-sp-calc-ux-philosophy.html` と同期。

## プロポジション（一文）

**対人準備の「本番想定編成の設計」を一瞬に近づけ、望まぬスキルを混ぜない真の必要 SP を返す攻略用計算機。**

サポカ性能の解説は他サイト。当アプリは編成パターン比較・切れ者有無・除外後の確定数値に特化する。

## 対象ユーザーと主ジョブ

| 項目 | 内容 |
|------|------|
| 対象 | ウマ娘ガチ層（LoH 級の長期準備） |
| 主ジョブ | **①編成設計時間の大幅短縮**（②因子・③本育成は他工程） |
| 体験 | 初回は組み立てが速い／本命は「真に欲しい数値」への信頼 |

ガチ勢はスピ3スタ1 vs スピ2スタ2 等の多択と、切れ者（約2〜5%取得）前提の時間コストを同時に抱える。当アプリは本育成前に「望まぬスキルを計上していない必要 SP」を机上で確定させる。

## UX 原則（7）

1. **真の必要 SP を返す** — 合計はユーザーが残したものだけ。除外・レギュは命題の一部。
2. **近似で盛らない** — 条件を満たさない計上をしない（例：たづな無しの中盤巧者をシナリオ常時にしない）。
3. **組み立ては速く、検証は深く** — 画像等で選び、内訳・由来は必要なときだけ。
4. **計算機の顔** — 攻略用の信頼感。玩具化しないが、見た目と操作は整える。
5. **他ツールを置き換えない** — 性能比較・個別解説は外。編成 → 計上 → 削る → 確定。
6. **前提が見える** — 切れ者・トレ Lv・継承・除外が合計の近くで読める。
7. **PC を主戦場** — スマホは補助。v1 前は **最低限から始め、対話でどこまでやるか決める**（下記「スマホ対応のスコープ」）。

### レイアウト切替（合意・2026-08-03）

| 幅 | 挙動 |
|----|------|
| **狭幅（≤1199px）** | **ギャラリー固定**。ギャラリー／スプリット切替 UI は出さない（狭幅ではモード切替に意味がない） |
| **広幅（≥1200px）** | ギャラリー／スプリットの **手動切替のみ** |

- **狭幅の境界: ≤1199px**（旧「自動」のスプリット境界と同じ。タブレット縦もギャラリー固定）
- **「自動（幅）」は削除**する（手動トグルと境界の重複で存在意義が薄い。既定はギャラリー）
- 本格最適化（専用ナビ・スプリット同等体験など）は v1 必須ではない

### 狭幅 UI・modebar（合意・2026-08-03）

| 項目 | 決定 |
|------|------|
| **modebar** | **≤1199px では非表示**（切替・説明文ごと。縦スクロールを増やさない） |
| **画像コピー／PNG** | 狭幅では **結果見出し横**（結果確認後も上へ戻らず出力可）。合計バーには載せない |
| **≥1200px** | 現状どおり modebar 右端に共有ボタン。ギャラリー／スプリット手動切替のみ |

**#2 で採らなかった案**: modebar に共有だけ残す → 上へ戻る必要あり。合計バー内 → 縦幅が増え UX 上不採用（2026-08-03 実機フィードバック）。

## 画面重心：デュアルレイアウト（確定・2026-08-02）

モック比較（v2〜H5）の結果、**ギャラリー（H2）とスプリット（H1）を同一情報モデルで切替**する方針に確定。  
編成（カード入れ替え・選択イベント）と表の削りはウェイトが近く、金イベント以外のヒントイベントも列／詳細で扱う。

### 2モード

| モード | 骨格 | 向く作業 |
|--------|------|----------|
| **ギャラリー（H2）** | 上段=圧縮ギャラリー＋列下要約／下段=表／下部バー=合計＋前提 | 編成の顔・バリアント比較・共有画 |
| **スプリット（H1）** | 上部=合計＋前提／左=ワイドドック＋イベント詳細／右=表 | PC1画面で削りと編成を同時 |

切替: **広幅では手動トグルのみ**（ギャラリー／スプリット）。**「自動（幅）」は削除**（合意 2026-08-03）。狭幅はギャラリー固定。情報モデルは共通。見た目は U-tools 寄りの紫クロム／世界観背景を基調（モック v2/H5）。

モック: [mockups/hybrid-h5-dual.html](./mockups/hybrid-h5-dual.html) · 一覧 [mockups/hybrid-index.html](./mockups/hybrid-index.html)

### イベント情報設計（A / B / C）

| 層 | 定義 | ユーザー行為 | 置き場所 |
|----|------|--------------|----------|
| **A. 選択式（サポカ）** | `single` / `toggle`。金・白・ステ分岐を含む。枚あたり 0〜数件 | **選ぶ** | 列下は要約。詳細はダイアログ（ギャラリー）または左ドックのイベント詳細ペイン（スプリット）。金スキル選択肢を最上段 |
| **B. 自動計上（サポカ）** | 実質1択で表に自動載るもの。「忘れてないよ」の透明性用 | **確認のみ**（編集不可） | **列下に短い「自動」表示**（金なら金トーン）。件数チップ→モーダルは採用しない |
| **C. シナリオ系** | シナリオリンク・RMJ など横断の選択（現状2つ）＋シナリオ自動 | 選ぶ／確認 | サポカ列に混ぜない。足元帯でリンク／RMJチップ。シナリオ自動は足元の折りたたみ（確認のみ）。継承は合計の隣 |

原則: **選ぶもの（A・Cの選択）と見せるだけ（B・シナリオ自動）を UI 上でも分ける。** 結果表は常に最終計上（B も含む）。

### B / シナリオ自動の置き場所（確定・2026-08-02）

- **サポカ自動（B）**: 各列下に要約のみ。編集不可。全体一覧モーダルは廃止
- **シナリオ自動**: 足元帯の `<details>`（件数サマリ＋展開一覧）。サポカ列には混ぜない
- 旧案の「件数チップ→モーダル」は不採用（スプリット正の実機確認後に現行方針へ確定）

### 旧・二マグネット記述について

2026-08-01 時点の「二マグネット＋下部バーのみ」は、ギャラリーモードの祖先。スプリット追加後も **前提は合計の近く**（原則6）を維持。左右タブ壳・強制フルページスナップは引き続き採用しない。

## ビジュアル（方針）

- 移植時のトークン正本は `app/css/`（現状 `foundation.css`）。モック確定後にデュアル用へ再塗装予定
- **見た目の参照**: モック v2/H5（U-tools 寄りの紫クロム `#463f70`・世界観背景・茶文字・幾何パネル）
- **フォント**: 本実装は可読ウェイトを落とさない（400＋薄いグレーのかすれを避ける）。候補は Zen Maru Gothic 等（モック）／既存 M PLUS Rounded の引き上げも可
- **ゲーム UI っぽさ**: 角丸・影・フォントで出す。表の可読性は維持
- 緑メイン（v3）は不採用（クロムは紫系）
