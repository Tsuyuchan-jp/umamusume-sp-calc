# UX — 思想

壁打ち確定版（2026-08-01）。renso ナレッジ: `umamusume-sp-calc-ux-philosophy.html` と同期。

## プロポジション（一文）

**対人準備の「本番想定編成の設計」を一瞬に近づけ、望まぬスキルを混ぜない真の必要 SP を返す攻略用計算機。**

サポカ性能の解説は他サイト。当アプリは編成パターン比較・切れ者有無・除外後の確定数値に特化する。

## 対象ユーザーと主ジョブ

| 項目 | 内容 |
|------|------|
| 対象 | ウマ娘ガチ層（LoH 級の長期準備） |
| 主ジョブ | **①編成設計時間の大幅短縮**（②因子・③本育成は他工程） |
| 体験 | 初回は組み立てが速い／本命は「真に欲しい数値」への信頼 |

ガチ勢はスピ3スタ1 vs スピ2スタ2 等の多択と、切れ者（約2〜5%取得）前提の時間コストを同時に抱える。当アプリは本育成前に「望まぬスキルを計上していない必要 SP」を机上で確定させる。

## UX 原則（7）

1. **真の必要 SP を返す** — 合計はユーザーが残したものだけ。除外・レギュは命題の一部。
2. **近似で盛らない** — 条件を満たさない計上をしない（例：たづな無しの中盤巧者をシナリオ常時にしない）。
3. **組み立ては速く、検証は深く** — 画像等で選び、内訳・由来は必要なときだけ。
4. **計算機の顔** — 攻略用の信頼感。玩具化しないが、見た目と操作は整える。
5. **他ツールを置き換えない** — 性能比較・個別解説は外。編成 → 計上 → 削る → 確定。
6. **前提が見える** — 切れ者・トレ Lv・継承・除外が合計の近くで読める。
7. **PC を主戦場** — 本格スマホは後段。軽い崩れで信頼を落とさない最低限は別枠。

## 画面重心：二段構え（C）

```text
上段ダッシュボード: ウマ娘 + サポカ6枠（視覚選択）+ 合計 + 前提チップ
下段作業台:        スキル一覧（含める/除外）・レギュ絞込・コピー
```

- **上段** = 編成バリアント比較の顔（入れ替えで合計・前提が即動く）
- **下段** = 真の数値への仕上げ（望まぬスキルを落とす）
- 上段を高くしすぎない。下段作業台がすぐ届くこと。

## 将来機能への制約

| 機能 | 方針 |
|------|------|
| メモリ | 1設計 = 1スナップショット（編成・前提・除外・絞込）。上段がプレビューになる |
| スクショ | 主面 = 上段（6枚＋合計＋前提）。除外リストは下段由来の付記 |

状態境界: `app/js/designSnapshot.js` を正とする。

## やらないこと（当面）

- サポカ性能解説の内製
- 近似計上
- 全サポカイベント網羅（優先枠方針は既存どおり）
- 本格スマホ最適化を PC UX より先に
- メモリ／スクショを思想確定前に先行実装

## PC 改善の順序

1. 本ドキュメント（済）
2. スナップショット境界の明示（`designSnapshot.js`）
3. 上段：視覚選択（`cardAssets.js` / ピッカー）
4. 上段：前提チップ
5. 下段作業台の維持・強化
6. 後続：メモリ → スクショ
